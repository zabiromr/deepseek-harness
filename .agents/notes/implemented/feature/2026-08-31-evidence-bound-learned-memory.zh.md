# Agent Note: 带证据的习得记忆

Status: implemented

[English](2026-08-31-evidence-bound-learned-memory.md) | 中文

## Problem

先前的一次改动为「自我改进」家族保留了十一个 `tool-*` 包名——反思、模式缓存、知识库、会话记忆、反馈聚合、插件与 schema 演进、元学习、对抗评审、基准测试、配置自动修复。它们每一个注册的工具都接受一个自由格式的 `action` 字符串、忽略它，并返回 `{ status: 'ok' }`。`dsh-self-improve-prompt` 把这十一个全部当作真实能力宣告给模型，且已发布的 bundle 以启用状态挂载它们。

这种状态比什么都没有更糟。总是报告成功的工具与真正可用的工具无法区分，因此被告知自己能够「捕获学到的教训」的模型，会把回合花在以为自己已经做到上。这些名称还编码了一套无人验证过的分类法：反思、模式缓存、元学习与反馈聚合，是同一个反馈循环的四个名字。

不过其背后的目标是真实的。数周内持续处理同一个仓库的框架，每次会话都在重新发现同样的事实——项目强制的某项约定、被证伪的某个假设、行为异常的某条命令——而这些内容没有被写在任何后续会话会读取的地方。

困难之处不在存储，而在可信度：不加甄别地累积的存储会变成提示词污染，而污染自身提示词的框架会一次比一次更糟。

## Decision

习得记忆能力缝 `ctx.memory` 持有持久的**教训**：一行关于该怎么做才不同的陈述、一段正文，以及指向会话日志的引用。有两条规则使该存储可信，且都归属于该能力缝而非任何提供方。

**每条教训都引用其证据。** `record`、`confirm` 与 `contradict` 都会在任何写入之前拒绝没有引用的调用。每条引用指明一个会话及其中事件的严格递增序号，因此读者可以把一条教训回放到产生它的日志上。无人能够核验的主张不是证据，而本框架从不注入这样的内容。该规则被有意在三处强制执行：服务边界拒绝无引用的请求，持久化 zod schema 拒绝从介质读回的无引用记录，而 `dsh-memory-domain` 的不变量伴生插件监视持久化写入事件流，使违规被归因到拥有它的包。

**地位会衰减，除非证据使其更新。** 一条教训的分数为 `confirmations - 2 * contradictions + 1`，且每经过 `halfLifeMs` 自上次确认起就减半。衰减是唯一的自动变化；地位上升只能通过 `confirm`，而它要求新的引用。状态对照两条下限下降——低于 `dormantFloor` 时教训离开提示词摘要，低于 `retireFloor` 时退役——且任何内容都不会被删除，因此曾经相信过什么始终保持可审计。

包的拓扑：

| 包 | 角色 |
|---|---|
| `memory/memory` | Service Definition：词汇、证据规则，以及每个提供方共享的评分与选择函数 |
| `memory/memory-domain` | 基于 `storage-domain` 的持久化提供方，`per-record` 布局 |
| `memory/memory-ephemeral` | 用于测试、schema 生成与沙箱的进程内提供方 |
| `memory/memory-prompt` | 受预算约束的提示词摘要 |
| `memory/memory-decay` | 定期重新分类清扫 |
| `feedback/tool-self-reflect` | 面向模型的捕获：`record`、`confirm`、`contradict` |
| `feedback/tool-knowledge-base` | 面向模型的检索，覆盖全部状态 |
| `feedback/self-improve-prompt` | 关于何时值得为其花费一轮的指引 |

选择、评分与复述都是该能力缝中的纯函数（`src/store.ts`、`src/score.ts`），因此两个提供方不可能在一条教训价值几何上产生分歧。衰减参数存放在服务上，因此摘要绝不可能按照清扫并未采用的半衰期来排序。每个服务方法都以拒绝而非在返回前抛出的方式报告失败；同步实现的提供方用该能力缝导出的 `promised` 辅助函数包装其函数体。

四个空壳包被删除——`tool-pattern-cache`、`tool-feedback-aggregator`、`tool-meta-learner`、`tool-session-memory`——因为它们为同一个循环取了四个名字。另有五个作为后续阶段的名称保留而留存（`tool-plugin-evolver`、`tool-schema-evolver`、`tool-config-autofix`、`tool-adversarial-reviewer`、`tool-automated-benchmarker`），并在已发布 bundle 中改为 `disabled: true`：在行为就位之前，保留的名称不得提供给模型。`dsh-self-improve-prompt` 被重写为只描述真实存在的内容。

### The group is a profile's choice, not the base composition's

`dsh-base` 将全部习得记忆条目声明为 `disabled: true`。每个启用的条目都会改变模型在每个会话首次请求时所见的内容：两份工具 schema 与一个提示词分节。让该组保持开启，就使已记录的记忆成为基础组合自身的属性；录制会话固定装置捕获了这一点——116 个场景中有 94 个在请求头上出现差异，横跨 `sdk`、`headless` 与 `acp` 三个 profile。这些条目在 `dsh-web-app` 中一同启用，因为工具通过提供方写入，而摘要才是让已写入的教训抵达后续会话的环节；只启用捕获工具的 profile 将为无人读取的教训付出 schema 代价。

这与预留条目已经遵循的规则相同，只是应用到了一项真正可用的能力上：智能体是否跨会话累积记忆是部署方的决定，而基础组合并不是一个部署。

## Two rules deliberately not adopted

**隐式确认。** 把「该教训在摘要中且会话进行顺利」当作一次确认很有诱惑力。那是披着证据外衣的幸存者偏差：它恰恰会抬高那些含糊到永远不会被反驳的教训。确认只能是显式的。

**对称权重。** 一次反驳减 2 而一次确认加 1，因此两次温和的确认无法挽救一条曾经误导过智能体的教训，而一次反驳就会让新教训变为负分——立即离开摘要，无需等待清扫。糟糕的记忆比没有记忆代价更高。

## Alternatives considered

**在 `storage-domain` 之上做一个自包含插件。** 代码约少 40%，且无需维护能力缝。已否决：它违反能力缝约定，而第二个存储——基于向量的检索、共享的团队存储——将没有可注册的接口。后续的配置演进与插件演进阶段也计划消费 `ctx.memory` 而非各自发明存储；这只有在能力缝存在时才成立。

**仅从会话日志派生记忆。** 无需新的持久化：教训就是会话事件，检索重跑 `session_query` 搜索。其吸引力在于证据*即是*存储，因此不可能与来源脱节。已否决，因为衰减需要可变分数而会话日志按设计是仅追加的，且在原始日志中搜索教训噪声很大。所采纳的划分把证据留在日志、把判断留在域中，并由后者指向前者。

**人工批准晋升。** 在人工晋升之前任何内容都不进入提示词。精度最高，但已否决，因为一旦无人关注循环就会停滞——而这恰恰否定了「框架在无人值守时跨会话自我改进」的意义。

**摘要按任务相关性排序。** 已否决：在提示词装配时任务尚不可知，因此那里的任何相关性信号都只能是猜测。由查询驱动的相关性是检索工具的职责。

## Consequences

框架现在能够在一个工作区内跨会话累积知识，受配置的字符预算约束，并通过衰减自我限制——没有人工甄别环节，也没有无界的提示词膨胀。

代价是八个包的表面积，每个都要承担仓库的逐文件 100% 覆盖率义务，外加每个包一份双语子系统页面与 README 配对。它还带来一份有意的滞后：提示词区块同步渲染而选择是异步的，因此摘要提供缓存快照，最多滞后一次装配。

除功能本身之外，它换来的是后续两个阶段可以依托的能力缝。配置演进与插件创作都需要一个地方记录尝试过什么、以及是否奏效；它们消费 `ctx.memory` 而不必各自发明存储，并随之继承证据规则。

检索是词法的——子串与标签匹配——因此措辞与查询不同的教训不会被找到。引用只检查形式而非存在性，因此伪造的引用会被存储，且只有在读取时才可发现。退役的教训绝不会被删除，因此大量记录的部署会无界地增长其存储。每项限制都记录在拥有它的包 README 中。

## Testing

八个包共 224 个测试，逐文件语句、分支、函数与行覆盖率均为 100%。承重用例包括：无引用的调用在任何写入之前被拒绝；通过一个宿主记录的教训被第二个宿主基于同一介质构建的摘要读到；一次反驳使教训退役且不重置其衰减时钟；一次确认使已淡出的教训复活；摘要对放不下预算的教训整条丢弃而非截断；以及持久化提供方的不变量在无引用记录到达写入事件流时触发。
